# **Front-End Interview Handbook, How Companies Really Hire Developers**

## 1. The Real Interview Flow Used by Product Companies

Most strong product companies follow a pattern very close to this:

1. Resume / Application Review
2. Online Coding Assessment
3. Technical Interview — JavaScript & Fundamentals
4. Technical Interview — Front-End System Design
5. Technical Interview — UI/UX & Product Thinking
6. Behavioral / Culture Fit Round
7. HR / Offer Discussion

Some companies merge rounds. Some split them.
But **these evaluations always happen**.

---

## 2. Stage 1 — Resume / Application Review

This is a technical filter, not a formality.

Companies like **Uber**, **Meta**, **Stripe** look for:

- Clear mention of tech stack with purpose
- Impact metrics (performance, users, speed, scale)
- Architectural decisions you made
- Ownership, not tutorial projects

### What gets rejected

- “Built a React app”
- No explanation of state management
- No real-world complexity

### What stands out

- “Implemented lazy loading reducing bundle size by 30%”
- “Designed reusable component system for dashboard”

---

## 3. Stage 2 — Online Coding Assessment

Used by **Google**, **LinkedIn**, **Stripe**

Conducted on platforms like:

- HackerRank
- Codility
- LeetCode
- CodeSignal

### What this round tests

- JavaScript fundamentals
- Logical problem solving
- Array / string manipulation
- Async behavior understanding
- Time complexity basics

### Example tasks

- Flatten an array
- Implement debounce
- Promise output prediction
- DOM traversal logic

If event loop is unclear, this round eliminates you.

---

## 4. Stage 3 — Technical Round: JavaScript & Fundamentals

This is the deepest JavaScript round.

Seen heavily in interviews at **Uber**, **Stripe**, **Google**.

### Topics they probe

- Closures and scope
- Hoisting
- Event loop (microtask vs macrotask)
- Prototypes and inheritance
- `this` keyword behavior
- Array methods: map, filter, reduce
- Writing utilities from scratch

### Example questions

- Write debounce / throttle
- How does Promise.all work internally
- Output prediction of async code
- Explain prototype chain with example

They check your **mental model of JavaScript**, not definitions.

---

## 5. Stage 4 — Front-End System Design Round

Very common at **Meta**, **Airbnb**, **Uber**.

This is not backend system design.
This is **component and state architecture**.

### What they test

- How you break UI into components
- Folder structure thinking
- State management choice (Redux, Context, local state)
- API caching strategy
- Performance strategy (lazy load, memo, code splitting)
- Reusability of components

### Real prompts asked

- Design a scalable dashboard
- Architect a chat application UI
- Structure a large React project
- Optimize app for low network users

They want to see how you think as an architect.

---

## 6. Stage 5 — UI/UX & Product Thinking Round

Common in product-focused companies like **Amazon** and **Netflix**.

### What they evaluate

- Accessibility understanding
- Responsive layout decisions
- Error states, loading states, empty states
- Visual hierarchy
- Why you place elements in certain positions

### Example questions

- Where should error messages appear and why?
- How would you redesign this layout for mobile?
- How would you improve accessibility here?

They test whether you think like a **user-focused engineer**.

---

## 7. Stage 6 — Behavioral / Culture Fit

Very important in big tech.

### They evaluate

- Communication clarity
- Conflict handling
- Ownership stories
- Problem solving in teams
- Handling production issues

You must explain technical experiences as stories with structure.

---

## 8. Stage 7 — HR / Offer Round

- Salary discussion
- Role expectations
- Joining timeline
- Negotiation

Not technical, but confidence matters.

---

## 9. How Different Companies Emphasize Different Stages

### Product Companies

(Uber, Meta, Stripe, Airbnb)

- Deep JavaScript
- Strong system design
- Product + UX thinking
- Clean architecture mindset

### Startups

- Practical feature building
- Real project discussion
- Speed of development
- Clean readable code

### Service Companies

- JavaScript fundamentals
- DSA style questions
- Communication

---

## 10. What Interviewers Are Secretly Scoring Throughout

Across all rounds they look for:

- Can you think in components
- Can you manage state logically
- Can you reason about performance
- Can you debug mentally
- Can you explain code clearly

Interview is not about answers.
It is about **how you think as a front-end engineer**.
